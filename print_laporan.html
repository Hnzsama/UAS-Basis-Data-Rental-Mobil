Bab I

Pendahuluan (Latar Belakang & Ruang Lingkup)

1.1 Latar Belakang Masalah

Seiring dengan perkembangan teknologi informasi yang sangat pesat, kebutuhan akan sistem pengolahan data yang akurat, cepat, dan terintegrasi menjadi hal yang mutlak bagi seluruh sektor bisnis, termasuk usaha jasa rental mobil. Selama ini, banyak pelaku bisnis rental berskala kecil menengah yang masih mengelola data transaksi mereka menggunakan pencatatan manual (kertas) maupun spreadsheet sederhana. Hal ini memunculkan banyak kerentanan, seperti risiko kehilangan data fisik, ketidakcocokan ketersediaan unit armada mobil, kesulitan menghitung akumulasi total denda keterlambatan secara riil, hingga lamanya pembuatan laporan bulanan untuk pihak manajemen.

Untuk mengatasi masalah-masalah di atas, dirancang sebuah sistem database relasional terintegrasi. Dengan database relasional, redundansi data dapat ditekan secara signifikan, anomali manipulasi data (insert, update, delete) dapat dihindari, dan konsistensi data tetap terjaga. Sistem ini mempermudah admin rental untuk memperbarui status unit mobil secara real-time, mendaftarkan identitas pelanggan baru, menghitung perkiraan biaya sewa di awal transaksi, serta memproses denda keterlambatan saat unit kendaraan dikembalikan.

1.2 Tujuan & Batasan Ruang Lingkup

Tujuan dari pengerjaan proyek ini adalah menghasilkan rancangan skema database rental mobil yang optimal (memenuhi kaidah 3NF) serta mengimplementasikannya ke dalam bentuk aplikasi CRUD (Create, Read, Update, Delete) multi-platform berbasis pemrograman Python (CLI) dan PHP (Web MVC). Adapun batasan ruang lingkup dari sistem ini meliputi:

  • Manajemen data master pelanggan (keanggotaan).
  • Manajemen armada mobil (merek, model, plat nomor, tarif sewa harian, status ketersediaan).
  • Manajemen transaksi sewa aktif (perhitungan tarif sewa berdasarkan rentang tanggal sewa dan rencana tanggal kembali).
  • Pencatatan pengembalian unit mobil beserta kalkulasi biaya denda jika aktual tanggal pengembalian melebihi dari rencana sewa awal.

Bab II

Keamanan & Analisis Kebutuhan Sistem

2.1 Deskripsi Proses Bisnis & Modul Sistem

Proses operasional dari Sistem Informasi Rental Mobil ini dikelompokkan ke dalam empat modul utama:

A. Modul Pelanggan (Keanggotaan)

Calon penyewa yang ingin meminjam kendaraan wajib mendaftarkan identitas pribadi mereka. Pendaftaran dilakukan dengan mengumpulkan data nama lengkap, nomor KTP (unik sebagai validasi legalitas hukum), nomor telepon aktif, dan alamat rumah. Admin akan menginput data ini ke database untuk referensi transaksi sewa.

B. Modul Mobil (Armada)

Admin rental mengelola data fisik mobil meliputi merek pabrikan, model/tipe mobil, nomor plat polisi (unik), serta harga sewa harian. Setiap unit mobil memiliki status ketersediaan ('Tersedia' atau 'Disewa') yang berubah dinamis.

C. Modul Transaksi Sewa

Saat menyewa, pelanggan memilih mobil yang berstatus 'Tersedia'. Admin mencatat tanggal mulai sewa dan rencana tanggal kembali. Sistem menghitung total biaya sewa berdasarkan jumlah hari dikali tarif mobil harian. Status mobil berubah otomatis menjadi 'Disewa' agar tidak disewa oleh pelanggan lain.

D. Modul Pengembalian & Denda

Ketika unit mobil dikembalikan, admin menginput tanggal aktual pengembalian. Jika tanggal aktual melebihi rencana tanggal kembali, sistem menghitung denda keterlambatan secara otomatis. Status mobil dikembalikan menjadi 'Tersedia'.

2.2 Pihak yang Terlibat (Aktor)

  1. Pelanggan (Customer): Memberikan berkas identitas untuk diregistrasi, memilih mobil, membayar sewa, serta membayar denda (jika terlambat).
  2. Admin Rental: Memiliki wewenang mengelola data master, membuat transaksi sewa, serta mencatat data pengembalian.

Bab III

Kardinalitas Hubungan Antar Entitas & Constraints

3.1 Analisis Kardinalitas

Untuk mendefinisikan hubungan antar data, ditentukan kardinalitas relasi antar entitas sebagai berikut:

  1. Pelanggan ke Transaksi Sewa (1 : N / One-to-Many):
    Satu pelanggan terdaftar dapat melakukan sewa berkali-kali secara berkala. Satu transaksi sewa hanya mengikat tepat satu pelanggan.
  2. Mobil ke Transaksi Sewa (1 : N / One-to-Many):
    Satu unit kendaraan mobil dapat disewakan berulang kali dalam beberapa transaksi sewa yang berbeda secara periodik. Satu nota transaksi sewa hanya memuat satu unit kendaraan.
  3. Transaksi Sewa ke Pengembalian (1 : 1 atau One-to-Zero-or-One):
    Satu transaksi sewa awalnya belum memiliki pengembalian (status mobil masih disewa). Ketika mobil dikembalikan, transaksi sewa akan memiliki tepat satu data pengembalian. Satu data pengembalian tidak dapat merujuk ke lebih dari satu transaksi sewa.

3.2 Integritas Data & Relational Constraints

Untuk menjaga integritas referensial data (referential integrity) antar tabel, dipasang aturan relasi berupa foreign key dengan opsi penanganan aksi penghapusan:

  • ON DELETE CASCADE pada Transaksi Sewa: Jika data pelanggan atau data mobil dihapus dari database, maka data transaksi sewa yang berhubungan dengan pelanggan/mobil tersebut akan terhapus otomatis secara berantai (cascade) guna menghindari anomali data yatim (orphan rows).
  • ON DELETE CASCADE pada Pengembalian: Jika transaksi sewa dihapus, maka data pengembalian yang merujuk padanya akan ikut terhapus.

4.3 Tahap Third Normal Form (3NF) Validation

Untuk memenuhi syarat **3NF**, tabel harus memenuhi **2NF** dan **tidak boleh mengandung ketergantungan transitif (transitive dependency)**. Yaitu atribut non-primary key tidak boleh menentukan atribut non-primary key lainnya. Seluruh data non-key pada tabel pelanggan, mobil, transaksi, dan pengembalian bergantung penuh pada Primary Key masing-masing. Oleh karena itu, skema di atas telah valid 3NF.

Bab VI

Implementasi DDL SQL (MySQL Schema)

Berikut adalah skema kueri DDL untuk membuat database dan struktur tabel-tabel di DBMS MySQL/MariaDB:

mysql -u root -p > source database_ddl.sql
-- Membuat Database
CREATE DATABASE uas_rental_mobil;
USE uas_rental_mobil;

-- Membuat Tabel Pelanggan
CREATE TABLE pelanggan (
    id_pelanggan INT AUTO_INCREMENT PRIMARY KEY,
    nama VARCHAR(100) NOT NULL,
    no_ktp VARCHAR(16) NOT NULL UNIQUE,
    no_telp VARCHAR(15) NOT NULL,
    alamat TEXT NOT NULL
);

-- Membuat Tabel Mobil
CREATE TABLE mobil (
    id_mobil INT AUTO_INCREMENT PRIMARY KEY,
    merek VARCHAR(50) NOT NULL,
    model VARCHAR(50) NOT NULL,
    plat_nomor VARCHAR(15) NOT NULL UNIQUE,
    harga_sewa_perhari INT NOT NULL,
    status VARCHAR(20) DEFAULT 'Tersedia'
);

-- Membuat Tabel Transaksi Sewa
CREATE TABLE transaksi_sewa (
    id_sewa INT AUTO_INCREMENT PRIMARY KEY,
    id_pelanggan INT NOT NULL,
    id_mobil INT NOT NULL,
    tgl_sewa DATE NOT NULL,
    tgl_kembali_rencana DATE NOT NULL,
    total_bayar INT NOT NULL,
    FOREIGN KEY (id_pelanggan) REFERENCES pelanggan(id_pelanggan) ON DELETE CASCADE,
    FOREIGN KEY (id_mobil) REFERENCES mobil(id_mobil) ON DELETE CASCADE
);

-- Membuat Tabel Pengembalian
CREATE TABLE pengembalian (
    id_kembali INT AUTO_INCREMENT PRIMARY KEY,
    id_sewa INT NOT NULL UNIQUE,
    tgl_kembali_aktual DATE NOT NULL,
    denda INT DEFAULT 0,
    FOREIGN KEY (id_sewa) REFERENCES transaksi_sewa(id_sewa) ON DELETE CASCADE
);

Query Laporan & Analisis Statistik SQL

Untuk mendukung kebutuhan laporan eksekutif dan analisis data operasional, berikut adalah query SQL JOIN dan fungsi agregasi (statistik):

mysql -u root -p > report_queries.sql
-- A. Query Laporan Status Sewa Aktif (Menampilkan nama pelanggan, model mobil, dan total biaya)
SELECT 
    t.id_sewa,
    p.nama AS nama_pelanggan,
    m.merek,
    m.model,
    t.tgl_sewa,
    t.tgl_kembali_rencana,
    t.total_bayar
FROM transaksi_sewa t
JOIN pelanggan p ON t.id_pelanggan = p.id_pelanggan
JOIN mobil m ON t.id_mobil = m.id_mobil;

-- B. Query Laporan Penerimaan Total Pendapatan Sewa per Bulan
SELECT 
    DATE_FORMAT(tgl_sewa, '%Y-%m') AS bulan,
    SUM(total_bayar) AS total_pendapatan_sewa,
    COUNT(id_sewa) AS jumlah_transaksi
FROM transaksi_sewa
GROUP BY DATE_FORMAT(tgl_sewa, '%Y-%m');

-- C. Query Menampilkan Mobil yang Paling Sering Disewa
SELECT 
    m.merek,
    m.model,
    COUNT(t.id_sewa) AS frekuensi_disewa
FROM transaksi_sewa t
JOIN mobil m ON t.id_mobil = m.id_mobil
GROUP BY t.id_mobil
ORDER BY frekuensi_disewa DESC
LIMIT 1;

8.1 Konsep Implementasi CRUD Python CLI

Implementasi CRUD berbasis Python difokuskan untuk interaksi cepat admin sistem melalui shell/terminal console. Program dirancang modular dengan pemisahan fungsi database dan interaksi antarmuka pengguna.

Logika program terdiri atas modul-modul berikut:

  • Connection Driver (mysql.connector): Berfungsi sebagai driver resmi MySQL untuk membangun koneksi TCP/IP dari script Python menuju server database MySQL/MariaDB.
  • Dotenv Parser: Program membaca variabel lingkungan (host, username, password, nama database) yang diisolasi di file .env. Hal ini penting untuk mengamankan data rahasia credentials dari kode utama.
  • Modular Query Executor: Setiap operasi (Create, Read, Update, Delete) dibungkus ke dalam fungsi python terpisah (misalnya create_mobil, read_mobil). Fungsi ini membuka koneksi, melakukan kueri, meng-commit perubahan, lalu menutup koneksi database secara tertib untuk mencegah memory leaks.
  • Console Menu Routing: Menggunakan struktur loop while True dan pengondisian if-elif-else untuk mengarahkan pengguna ke sub-menu pengelolaan mobil maupun pelanggan.

Program ini juga mengimplementasikan penanganan error (exception handling) menggunakan blok try-except untuk menangkap kegagalan masukan tipe data angka oleh user, sehingga program tidak crash di tengah eksekusi.

PHP Database Config (`config.php`) Code

File `config.php` memuat environment variables dari file `.env` dan membungkus koneksi database ke dalam class singleton `Database` menggunakan mysqli driver:

php/config.php
<?php
// Load environment variables dari file .env secara manual
function load_dotenv($path) {
    if (!file_exists($path)) return;
    $lines = file($path, FILE_IGNORE_NEW_LINES | FILE_SKIP_EMPTY_LINES);
    foreach ($lines as $line) {
        $line = trim($line);
        if (empty($line) || strpos($line, '#') === 0) continue;
        if (strpos($line, '=') !== false) {
            list($key, $value) = explode('=', $line, 2);
            putenv(trim($key) . "=" . trim($value, "\"' "));
        }
    }
}
load_dotenv(__DIR__ . '/.env');

class Database {
    private static $conn = null;

    public static function connect() {
        if (self::$conn === null) {
            $host = getenv("DB_HOST") ?: "localhost";
            $user = getenv("DB_USER") ?: "root";
            $pass = getenv("DB_PASSWORD") ?: "";
            $db   = getenv("DB_DATABASE") ?: "uas_rental_mobil";

            // Sembunyikan output detail error SQL bawaan untuk mencegah info leak
            mysqli_report(MYSQLI_REPORT_OFF);
            self::$conn = new mysqli($host, $user, $pass, $db);
            if (self::$conn->connect_error) {
                error_log("Database connection failed: " . self::$conn->connect_error);
                die("Koneksi database gagal. Periksa konfigurasi Anda.");
            }
        }
        return self::$conn;
    }
}

PHP Model Master Mobil (`models/Mobil.php`) Code

Berikut adalah file model class `Mobil` yang bertugas berinteraksi secara aman dengan database MySQL menggunakan prepared statement:

php/models/Mobil.php
<?php
require_once __DIR__ . '/../config.php';

class Mobil {
    public static function getAll() {
        $db = Database::connect();
        $result = $db->query("SELECT * FROM mobil ORDER BY id_mobil DESC");
        $cars = [];
        if ($result) {
            while ($row = $result->fetch_assoc()) { $cars[] = $row; }
            $result->free();
        }
        return $cars;
    }

    public static function create($merek, $model, $plat_nomor, $harga_sewa, $status = 'Tersedia') {
        $db = Database::connect();
        $stmt = $db->prepare("INSERT INTO mobil (merek, model, plat_nomor, harga_sewa_perhari, status) VALUES (?, ?, ?, ?, ?)");
        if ($stmt) {
            $stmt->bind_param("sssis", $merek, $model, $plat_nomor, $harga_sewa, $status);
            $success = $stmt->execute();
            $stmt->close();
            return $success;
        }
        return false;
    }

    public static function delete($id) {
        $db = Database::connect();
        $stmt = $db->prepare("DELETE FROM mobil WHERE id_mobil = ?");
        if ($stmt) {
            $stmt->bind_param("i", $id);
            $success = $stmt->execute();
            $stmt->close();
            return $success;
        }
        return false;
    }
}

Penutup (Kesimpulan & Saran)

10.1 Kesimpulan

Berdasarkan seluruh tahapan perancangan, normalisasi, hingga implementasi program aplikasi pada database **Sistem Informasi Rental Mobil**, diperoleh kesimpulan sebagai berikut:

  1. Efisiensi Normalisasi: Dekomposisi database hingga bentuk Third Normal Form (3NF) berhasil memecah data menjadi 4 tabel terpisah (Pelanggan, Mobil, Transaksi Sewa, Pengembalian). Hal ini menekan redundansi data secara maksimal dan mengeliminasi anomali ketika memproses data.
  2. Integritas Hubungan Referensial: Penggunaan konstrain foreign key dengan opsi ON DELETE CASCADE menjaga keutuhan data relasional, menghindari data yatim (orphan data), dan memastikan database mematuhi asas ACID.
  3. Keamanan Terjamin: Pemanfaatan *Prepared Statements* baik di Python CLI (menggunakan driver mysql.connector) maupun PHP Web MVC (menggunakan MySQLi bind_param) terbukti sukses mengamankan parameter kueri dari ancaman injeksi SQL (SQL Injection).

10.2 Saran Pengembangan

Untuk pengembangan sistem informasi database rental mobil ini di masa depan, penulis menyarankan beberapa poin berikut:

  • Autentikasi Pengguna: Menambahkan tabel user administrator beserta hash password aman (misalnya bcrypt) untuk autentikasi login multi-level admin dan pelanggan.
  • Metode Pembayaran: Mengintegrasikan sistem kasir pembayaran digital (payment gateway) untuk mencatat histori invoice dan pembayaran non-tunai.
  • Tracking GPS Armada: Menghubungkan modul tracking armada real-time menggunakan koordinat peta (maps API) guna memantau posisi unit yang sedang disewa.
